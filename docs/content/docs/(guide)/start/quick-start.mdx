title: Quick start
description: Create a profile for a host, install it, and open its desktop.

---

This walks through a first host from berth's terminal UI. The example uses an Ubuntu 26.04 server you can already reach over SSH. The other ways to install differ only in what you choose on the Install tab.

<Callout title="Try it without a machine">
  The [container](/docs/deploy/container) runs the same desktop on Docker, and [QEMU](/docs/deploy/qemu) runs a whole host in a VM.
</Callout>

<Steps>
<Step>

### Create the host

```bash
berth studio
```

A name berth does not know starts a new profile, saved as `~/.config/berth/hosts/studio.json`. Running `berth` alone opens the home screen, where `n` creates a host.

</Step>
<Step>

### Choose how to install

The profile opens on **Install** (key `1`). Choose **Existing host over SSH** under **How To Install**, then enter the address in **SSH host**: an IP, a hostname or a `Host` alias from your SSH configuration. The Tailscale settings are on this tab too.

The set-up has four tabs. Each one depends only on the tabs before it.

| Tab | Key | What it holds |
| --- | --- | --- |
| Install | `1` | How to install, and what that needs: the address, the hostname, Tailscale |
| Features | `2` | What gets installed |
| Settings | `3` | Everything with a default, such as accounts, registries and secrets |
| Run | `4` | Every open problem, and the button that installs |

Tab and Shift+Tab switch tabs too. Ctrl+S saves the profile at any point.

</Step>
<Step>

### Choose what to install

**Features** (key `2`) lists the coding agents, T3 Code, tool categories, browsers, Cockpit, Docker and plugin features. Space on a group heading switches the whole group.

<Screen name="features" alt="The Features tab: Coding Agents, Agent Orchestrator, Development Tools, Browsers, Desktop, Host Services and System groups with switches" />

</Step>
<Step>

### Check the settings

**Settings** (key `3`) holds what has a default. That covers the *operator*, your account on the host, and the *agent* account the coding agents use. SSH keys found in `~/.ssh` and in ssh-agent are offered as suggestions (Right or F2). Each account can take several, and the operator also takes [the key of berth itself](/docs/reference/profile#the-key-of-berth-itself). `c` on that field copies it.

On a password hash field, F4 generates a password and stores its hash, and F5 hashes one you type. Generated passwords are written next to the profile as `studio.credentials.json`.

<Screen name="accounts" alt="The Settings tab with the operator and agent accounts, Access with SSH hardening, registries and secrets" />

</Step>
<Step>

### Install

**Run** (key `4`) lists every problem that stops the install, under the name of the tab it belongs to. Each tab also lists its own problems at the bottom. Fix them, and press Enter on **Run**.

<Screen name="install-cloud" alt="The Run tab listing the open problems by tab, a warning, and the Run and Save buttons" />

The other methods are on [Deploying](/docs/deploy).

</Step>
<Step>

### Use the host

Once the host has an SSH address, `berth studio` opens its **overview**. Run **Status** to check it, then **Access links and desktop password** for the address of the desktop.

<Screen name="overview" alt="The overview of a host with its tasks" />

</Step>
<Step>

### Sign the agents in

Installing a coding agent does not sign it in. Under **Sign-In**, **Sign in to Claude Code** and the others run the tool's sign-in on the host and show its link, which you open in your own browser. See [Sign-ins](/docs/use/sign-ins).

</Step>
</Steps>
