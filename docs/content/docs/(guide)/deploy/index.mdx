The install methods all run the same Ansible role with the settings of the host's profile. Choose one on the **Install** tab of a host, or use the matching command.

| Method | For | Command |
| --- | --- | --- |
| USB installer | A blank laptop or PC; erases a disk and installs Ubuntu | `berth iso HOST` |
| Cloud-init seed | A fresh cloud machine at a provider that takes cloud-init | `berth seed HOST` |
| Machine from a provisioner | A container or virtual machine that a plugin creates, such as on Docker or Incus | `berth provision HOST PLUGIN/ID` |
| Existing host over SSH | An Ubuntu 26.04 machine you can log in to | Install tab |
| This machine or an inventory | The machine berth runs on, or your own Ansible inventory | Install tab, or `ansible-playbook` |
| Container image | Trying the desktop on Docker | Install tab, or `docker compose` |

The target is Ubuntu 26.04 on amd64. The USB installer installs it, and the other methods expect it.

## Before you run

The Install tab lists what is still missing above **Run**, and Run does not start while a problem is listed. Warnings, such as SSH being open to any address, are listed too but do not stop it.

Builds run inside berth with their output and a progress bar. Esc cancels and Enter returns. Installing over SSH and *This machine or an inventory* continue in the normal terminal, where Ansible and SSH can ask for passwords, and return to berth when they finish.

<Callout type="warn" title="Use dedicated machines">
  The role installs services, changes the firewall and grants the agent sudo. With a blank inventory, *This machine or an inventory* provisions **the machine you are sitting at**. Only do that on a dedicated box.
</Callout>
