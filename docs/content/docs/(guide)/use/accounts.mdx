Every host has two accounts, set under **Operator Account** and **Agent Account** on the host's **Settings** tab:

| Account | Default name | For |
| --- | --- | --- |
| Operator | `ops` | You: SSH, Cockpit, the console and the laptop's login |
| Agent | `agent` | The coding agents, T3 Code and the virtual desktop; home `/home/agent` |

Separate accounts keep sessions apart, but they do not isolate data from an agent that can become root.

## The operator

The operator is the account berth manages the host with. On every host it:

- Uses sudo without a password. The role writes `/etc/sudoers.d/99-devbox-operator`.
- Logs in over SSH with keys only. `/etc/ssh/sshd_config.d/00-devbox-operator.conf` holds a `Match User` block that allows only key logins for it, whatever **SSH hardening** says.
- Takes the SSH key of [each berth](/docs/reference/profile#the-key-of-berth-itself) that installs or applies the host. Each of these keys has a block of its own in the operator's `~/.ssh/authorized_keys`, and no later apply removes it. An apply stops with an error before it changes SSH if that key is not there.

None of these can be switched off, on laptops either.

The operator's password is optional and only for local logins: the console, the laptop's graphical login and Cockpit. Cockpit checks it through PAM, not through SSH. Without a password the account's password field is `*`. No password logs in then, and SSH keys still do.

| Install | Operator password |
| --- | --- |
| USB installer | Required. The Ubuntu installer needs one for the account it creates |
| Cloud seed or created machine | Optional |
| Apply over SSH or to this machine | Optional. An empty one leaves the account's password as it is |

## Passwords

On a password hash field, F4 generates a password and stores its hash, and F5 hashes a password you type. Generated passwords are written next to the profile as `NAME.credentials.json` with mode 0600. The profile itself only stores hashes.

- An empty agent password locks password login for the agent.
- Turning off the agent's passwordless sudo requires an agent password.

## The first apply as another account

An existing machine may not have the operator yet. berth then applies as an account of the machine's own, the profile's SSH user. When sudo prompts that account for a password, switch on **Ask for sudo password** on the Run tab, or set `builder.ask_become_pass`. berth asks for the password when it applies and when it connects. `BERTH_SUDO_PASSWORD` gives it where nobody can type it.

When the SSH user is the operator, berth switches **Ask for sudo password** off again once the apply has worked, as the operator's sudo doesn't prompt for one from then on. Any other SSH user keeps its setting.

A profile from before these rules may still say `"operator_passwordless_sudo": false` or `"berth_ssh_key": false`. berth reads it as usual and ignores both. The next apply gives the operator sudo without a password and the key of berth.

## Agent privileges

`agent_privileges` in the profile, **Agent privileges** on the Settings tab:

| Level | The agent's sudo |
| --- | --- |
| `full` | Everything, without a password. For machines you can throw away |
| `limited` | `apt-get` and `apt` with `update`, `install`, `upgrade`, `dist-upgrade`, `full-upgrade` and `autoremove`, and `systemctl restart` of plugin services that run as the agent. New profiles start here |
| `none` | Nothing |

Under `limited` and `none` the agent cannot change SSH, Tailscale, the firewall, the operator's account or berthd.

<Callout type="warn" title="limited guards against accidents, not intent">
  What a package installs runs as root, so an agent that may install packages can become root if it tries. An agent with `full` can administer the whole host. Use a dedicated machine or VM either way.
</Callout>

A profile without the setting keeps what it had before the setting existed: `full`, or sudo with the agent's password when `agent_passwordless_sudo` is off.

## Logging in as the agent

On the host, switch from the operator to the agent:

```bash title="On the host"
sudo -iu agent
```

From your machine, `berth ssh HOST --agent` opens a shell as the agent, and the overview's **Terminal** switches between the two accounts with Space.
