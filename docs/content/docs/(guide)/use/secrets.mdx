berth keeps secret values on your machine and sends them to a host when you say so. The host's profile only records which secrets it gets and how.

| What | Where | Notes |
| --- | --- | --- |
| Secret values and registry passwords | `~/.config/berth/secrets.json` | Readable by you only (mode 0600), not encrypted |
| Which secrets and registries a host gets | The host's profile | Names only |

On the host everything belongs to the agent account, in plain files. The agent can read everything you send it.

<Callout type="warn">
  Give the agent tokens limited to what it should do, and let them expire.
</Callout>

## Send a secret

<Steps>
<Step>

### Store the value

```bash
berth secret set github          # asks for the value without showing it
echo "$TOKEN" | berth secret set github
```

Or use the **Secrets** tab of the home screen (`4`). Enter on **+ Add secret** asks for a name and the value, Enter on a secret replaces its value, `x` twice removes it. Values are never shown.

</Step>
<Step>

### Give it to the host

As an environment variable or as a file, with an optional mode:

```bash
berth host studio secret github env GH_TOKEN
berth host studio secret deploy-cert file ~/.config/acme/cert.pem 0600
```

Or on the host's **Secrets** set-up tab, where you type a variable name such as `GH_TOKEN` or a path such as `~/.config/app/token`.

<Screen name="secrets" alt="A host's Secrets tab: the github secret given as variable GH_TOKEN" />

</Step>
<Step>

### Send them

```bash
berth run studio secrets
```

Or **Secrets and registry logins** under Sync on the overview.

</Step>
</Steps>

Check what a host is given with `berth host studio`, and stop giving one with `berth host studio secret github off`. List the stored names with `berth secret`, and delete a value with `berth secret remove github`.

## On the host

Each send replaces what was installed before, so removing a secret and sending again removes it from the agent's environment. Files that were written stay. Delete them on the host.

Environment variables are written to `~/.config/devbox/secrets.env` of the agent, which `box exec` and the agent's shells read, and in a second file that the T3 Code service reads. Programs that are already running, T3 Code included, see a new value only after a restart. A value of several lines has to be a file.

## GitHub

Create a fine-grained token limited to the repositories the agent should work on, with *Contents* and *Pull requests* set to read and write. Then:

```bash
berth secret set github
berth host studio secret github env GH_TOKEN
berth run studio secrets
```

`gh` uses that variable, and berth sets `gh` as git's credential helper for github.com, so `git clone`, `git push` and `gh pr create` work for the agent without a sign-in.

<Callout type="warn">
  The token is the only limit on what the agent can push. Protect branches on GitHub's side.
</Callout>
