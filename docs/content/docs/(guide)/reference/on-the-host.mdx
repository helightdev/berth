| Path | Holds |
| --- | --- |
| `/etc/devbox/AGENT.md` | The description of the machine for agents (below) |
| `/etc/devbox/guides/` | Longer guides for the desktop, graphics, and each plugin feature with a guide |
| `/etc/devbox/expected-commands` | Commands the self-test requires, including those plugins list |
| `/etc/devbox/mcp.json` | The desktop MCP server, to merge into an MCP client's configuration |
| `/etc/berth/*.json` | berthd's settings, tasks, services and channel topics |
| `/usr/local/lib/berth/tasks/` | The scripts of berth's own tasks |
| `/var/lib/devbox/provision-state` | The state of the first-boot provisioning |
| `/var/lib/devbox/ready` | Written when Ansible converged, with the release's digest |
| `/var/lib/devbox/toolchains.json` | The runtime versions that were installed |
| `/var/lib/berth/` | berthd's state: session transcripts and the kept channel messages |
| `/run/berth/` | berthd's sockets, host level and agent level |
| `~/.config/devbox/secrets.env` | Secrets given as environment variables |
| `~/.config/tigervnc/password` | The desktop's password |
| `/srv/agent/workspaces`, `/srv/agent/artifacts` | Where agents keep projects and output, such as screenshots |

## Services

| Unit | Runs |
| --- | --- |
| `berthd.service` | berthd, as root |
| `berth-svc-PLUGIN-NAME.service` | One per [plugin service](/docs/extend/services) |
| `devbox-provision.service` | The first-boot provisioning of a USB or cloud install, with a retry timer |
| The agent's user services | The virtual desktop, noVNC and T3 Code |

## What agents read

`/etc/devbox/AGENT.md` is generated on each host from what was installed there. It lists the tool categories, the coding agents and the CPU or GPU rendering, with one line per plugin feature. It stays short and points to `/etc/devbox/guides/` for the rest.

The agents' own instruction files reference it, without overwriting existing text:

| Agent | File |
| --- | --- |
| Claude Code | `~/.claude/CLAUDE.md` |
| Codex | `~/.codex/AGENTS.md` |
| Pi | `~/.pi/agent/AGENTS.md` |

GUI programs, T3 Code and the commands it starts share the desktop's `DISPLAY`, Xauthority and session bus. Ordinary shell commands get them with [`box exec`](/docs/reference/box#desktop-environment).

## The self-test

`devbox-smoke` is the **Self-Test** task. It checks:

- that the expected commands exist
- llvmpipe on the shared desktop and in Xvfb, and lavapipe enumeration
- that the coding clients start with `--version`
- the desktop, browsers and artifact tools
- whatever the host's plugins add

 It saves graphics reports and screenshots in its artifact directory.

```bash
berth run studio smoke
```

The browser check starts Playwright's Chromium with its sandbox on. How Chromium sandboxes itself depends on the machine:

| Machine | Sandbox |
| --- | --- |
| Laptop, server or virtual machine | A user namespace, which an AppArmor profile of the role allows |
| Container, such as one from Incus or Docker | Chromium's setuid helper, which the role puts beside the Chromium it installs |

A container can't use the user namespace, because Ubuntu's AppArmor on the machine that runs the container takes away the rights Chromium needs in it. A Chromium that the agent installs itself in a container has no helper, so it can't start sandboxed. When the sandbox can't start, the check says so, names the kind of machine and fails. Chromium's own output is in `browser-error.txt` in the artifact directory. The [container image](/docs/deploy/container) runs under Docker's default seccomp profile, where neither way works, and there the check is listed as skipped.
