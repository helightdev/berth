A profile is a JSON file that describes one host. berth writes it from the set-up tabs. The fields below can also be edited by hand. Settings of the Ansible role go under `ansible_vars`, and how berth reaches and installs the host under `builder`.

```json title="~/.config/berth/hosts/studio.json (excerpt)"
{
  "hostname": "studio",
  "profile": "laptop",
  "operator_username": "ops",
  "operator_ssh_public_keys": ["ssh-ed25519 AAAA... you@workstation"],
  "agent_username": "agent",
  "agent_privileges": "limited",
  "target_disk_mode": "auto",
  "keyboard": "us",
  "ansible_vars": {
    "devbox_plugin_features": ["claude/cli", "codex/cli", "t3/server", "github/cli"]
  },
  "builder": { "ssh_host": "studio.example.ts.net", "ssh_user": "ops" }
}
```

<TypeTable
  type={{

  }}
/>

A profile written before the lists has one key in `operator_ssh_public_key` or `agent_ssh_public_key`. berth still reads it, and moves it into the list when the keys are next changed.

### The key of berth itself

Each berth makes an ed25519 key of its own the first time it needs one, and keeps it as `id_ed25519` in its data directory. The operator of a host takes it along with the keys in the profile, so the berth that set a host up can log in to it without a key of yours. That matters most for a [berth server](/docs/use/server), which has no keys until you give it some. berth offers the key over SSH unless the profile has a key file set.

`berth key` prints the public half. Turn **This berth's SSH key** off in Accounts, or set `berth_ssh_key` to `false`, for a host that should only take the listed keys.

## Role settings (`ansible_vars`)

Any `devbox_` setting of the role. The ones the terminal UI edits:

| Setting | In berth | Default |
| --- | --- | --- |
| `devbox_plugin_features` | Features tab | `claude/cli`, `codex/cli`, `pi/cli`, `t3/server`, `github/cli` |
| `devbox_tools_*` (one per [category](/docs/reference/tools#tool-categories)) | Features tab | on |
| `devbox_install_playwright` | Features tab | on |
| `devbox_software_rendering` | Software graphics | on |
| `devbox_geometry` | Desktop size | `1600x900` |
| `devbox_bootstrap_ssh_cidr` | Recovery SSH CIDR | none |
| `devbox_harden_ssh` | SSH hardening | on |
| `devbox_install_cockpit` | Cockpit web console | on |
| `devbox_install_docker` | Docker on host | on |
| `devbox_install_tailscale` | Tailscale | on |

Others, such as `devbox_tailscale_serve`, the agent versions and the backup settings, are described where they are used. All defaults are in [`defaults/main.yml`](https://github.com/helightdev/berth/blob/main/ansible/roles/devbox/defaults/main.yml).

## Beside the profile

| File | Holds |
| --- | --- |
| `NAME.credentials.json` | Generated passwords, mode 0600 |

Secrets and registries a host gets are listed in the profile by name (`secrets`, `registries`). Their values stay in `~/.config/berth/secrets.json`.
